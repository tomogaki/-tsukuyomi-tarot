# つくよみタロット よみ 移植プロジェクト（Vercel + Supabase）

現在のMuse版「つくよみタロット よみ」と同等のデザイン・文面・機能を、外部公開できる Next.js + Supabase 構成で再構築したプロジェクト一式です。公開URL（`https://〜.vercel.app`）が発行されるので、Instagramプロフィールのリンクに貼れます。

## 構成
- Next.js 14（App Router, TypeScript）
- Supabase: PostgreSQL + Auth（占い師ログインはメール + パスワード）
- デプロイ先: Vercel
- デザイン: ダークネイビー × アイボリー、アンティークゴールド、明朝体。屋号ワードマーク（金の細線三日月＋グラデーション文字）はヘッダーとフッターで共通です。

## セットアップ手順（初心者向け）

### STEP 1: アカウント作成
GitHub / Vercel / Supabase のアカウントを作成します（まだの場合は各公式サイトから無料登録）。

### STEP 2: このプロジェクトを GitHub に置く
このフォルダ一式を GitHub の新規リポジトリにアップロード（push）します。

### STEP 3: Supabase プロジェクト作成
Supabase で新規プロジェクトを作成します（名前は任意、例: `tsukuyomi-tarot`）。

### STEP 4: データベース作成（schema.sql 実行）
Supabase ダッシュボード > SQL Editor を開き、`supabase/schema.sql` の内容をすべて貼り付けて Run します。
テーブル（listings / applications / messages / readings / feedback / profile）、初期募集3件（恋愛・仕事・人間関係／各定員5名）、プロフィール初期文、完了ロック用トリガー、RLSポリシーが作成されます。

### STEP 5: 認証設定と占い師アカウント
1. Supabase > Authentication > Providers > Email を有効化します。
2. **重要: 公開前に必ず占い師（よみ）ご自身が最初に登録してください。** サイトの `/login` 画面で「新規登録」し、そのアカウントでマイページを使います。
3. なりすまし登録を防ぐため、登録後は Supabase > Authentication > Providers > Email の「Allow new users to sign up」を OFF にすることを推奨します（ログイン自体は引き続き可能です）。

### STEP 6: 環境変数を Vercel に登録
Vercel で GitHub リポジトリを Import し、Settings > Environment Variables に以下を登録します。
- `NEXT_PUBLIC_SUPABASE_URL` — Supabase > Settings > API > Project URL
- `NEXT_PUBLIC_SUPABASE_ANON_KEY` — 同画面の anon key
- `SUPABASE_SERVICE_ROLE_KEY` — 同画面の service_role key（秘密情報・公開禁止）

ローカル開発時は `.env.example` を `.env.local` にコピーして値を入れます。

### STEP 7: デプロイ
Vercel で Deploy を実行し、`https://〜.vercel.app` の URL が発行されたらスマホで確認します。そのURLを Instagram プロフィールのリンク欄に貼れば、お客様がサイト内でメニューを選んで応募できるようになります。

### STEP 8: 動作確認（通しテスト）
1. ホーム表示（見出し2行・説明文4行・特徴3カード・プロフィール）を確認
2. 募集一覧でカテゴリタブ（すべて／恋愛／仕事／人間関係）の切り替えと残り人数を確認
3. 詳細からテスト応募（合言葉の注意表示・完了画面でのお名前／合言葉の大きな表示を確認）
4. ホーム下部「応募済みの方はこちら」でお名前＋合言葉検索 → 鑑定ルーム入室
5. 占い師でログイン → マイページで応募確認 → ルームで返信・鑑定書作成（11ポジション＋まとめ3項目）→ 送信
6. 相談者側で鑑定書表示と感想送信 → 案件が「完了（感想あり）」になり、メッセージ・感想がロックされることを確認

## 実装済みの現行仕様
- ホーム: 肩書き「― 月読み ―」、見出し「カードがそっと／未来を教えてくれる」（2行）、説明文4行、ゴールドボタン「募集メニューを見る・応募する」、特徴3カード（2枚目は「10枚のストーリーに『対策の1枚』をプラスした11枚引き」）、よみプロフィール（指定文・改行再現）、「応募済みの方はこちら」（鑑定書ありの応募には「感想はこちらから →」ボタン、合言葉再発行不可の一文を常時表示）
- 募集一覧: バナー「募集メニュー」、タブ切替、タロットカード風カード（濃紺グラデ・金の二重線・四隅装飾、「ケルト十字」ピルバッジ、無料・残り人数・満員御礼）
- 詳細＆申し込み: 招待状風（ベージュ＋金の二重線）、月・星・太陽の線画、ケルト十字11枚の並び図、「占えないこと」＋「お約束事項」5項目、フォーム（お名前・合言葉・相談内容・同意チェック）、合言葉欄下の金枠注意、完了画面でお名前と合言葉を大きく表示
- 鑑定ルーム: お名前＋合言葉で入室、1対1メッセージ、鑑定書（魔導書風：濃紺・金の二重線フレーム、11ポジション＝三日月バッジ＋補足文、カード名＋正位置／逆位置バッジ、まとめ3項目、署名と三日月のグロー、締め4行）、感想フォーム（送信で同文面がメッセージにも届き案件完了→両側ロック）、ルーム上部の感想ジャンプボタン、占い師ビューの案内枠と「相談者側の見え方を確認する（プレビュー）」
- マイページ（占い師用）: ログイン、募集の作成・停止／再開・削除、応募一覧（ステータス表示）、鑑定書作成フォーム（11ポジション×タロット78枚プルダウン＋正位置／逆位置、「AI（ChatGPT）用の鑑定作成プロンプトをコピー」ボタン＋手動コピー用テキスト、「鑑定文（最終編集）」テキストエリア）

## ⚠️ 合言葉（簡易認証）についての注意
現行仕様を踏襲し、相談者の入室は「お名前＋合言葉」の平文照合です。合言葉はデータベースに平文で保存され、再発行はできません（忘れた場合は入室できない仕様で、サイト内3か所に明記しています）。
- 合言葉は推測されやすい語（誕生日など）を避けるよう、応募者への案内文で促してください。
- RLSは「アプリ側で必ず名前＋合言葉の等値条件でのみ検索する」前提の最小公開設定です。有料化や個人情報を扱う段階になったら、Edge Function 経由の照合＋合言葉のハッシュ化への移行を強く推奨します。
- `SUPABASE_SERVICE_ROLE_KEY` は絶対にブラウザや公開コードに含めないでください（Vercelの環境変数のみ）。

## ローカル確認
```bash
npm install
npm run dev
npm run build
```
環境変数未設定の場合はデモ表示（初期募集3件の表示のみ・送信不可）になります。表示確認だけならそのまま確認できます。

## 補足
- プロフィール文の初期値は `src/lib/constants.ts` の `PROFILE_BIO` と schema.sql の初期行に同文で入っています。マイページで保存した文面をホームに常時反映したい場合は、ホームをサーバーコンポーネント化して `profile` テーブル（id=1）を読むよう1か所つなぎ替えてください。
- 募集の「編集」はマイページで停止／再開・削除・新規作成で運用する形にしています（タイトル等の直接編集が必要になったら listings への update を追加してください）。
